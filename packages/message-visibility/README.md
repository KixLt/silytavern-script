# 楼层可见性（酒馆助手脚本）

在输入栏上方加一条开关栏，决定**哪些楼层会发给 AI**。酒馆本身只提供单条 `/hide`，
这个脚本把「楼层可见性」变成一张能扫读、能批量操作的表。

界面按 [shadcn/ui](https://ui.shadcn.com) 的 token 与组件规格实现（button / switch /
tabs / badge / input / popover）。脚本是 IIFE 注入，引 React + Radix 会让体积翻几倍，
所以用纯 CSS 复刻同一套设计语言，而不是把组件库打包进来。

```
[图标] 楼层可见   [隐藏 3]   [定时 2]
   收起后只留状态：
[图标] 3/40 - 隐藏
```

| 能力 | 说明 |
| --- | --- |
| 单条开关 | 每层右侧一个开关，关掉即对 AI 隐藏（等价于酒馆的「隐藏消息」） |
| 筛选 | 顶部 `全部 / 用户 / AI` 切换列表里显示的内容 |
| 一键全部 | `全部可见` / `全部隐藏`，系统楼层不受影响 |
| 可见窗口 | `只让最近 N 轮可见`：更早的楼层一次性隐藏，边界保留对应的用户提问 |
| 定时规则 | 点某一层在手风琴里设置「N 轮后隐藏 / N 轮后可见」，逐轮倒数并自动执行 |
| 状态条 | 收起后工具栏只显示「隐藏数/总数 - 上一条状态」 |

## 在酒馆中使用

酒馆助手 ‣ 脚本 ‣ 新建脚本，内容只写一行：

```js
import 'https://cdn.jsdelivr.net/gh/KixLt/silytavern-script@master/dist/message-visibility/index.js'
```

保存并启用即可，输入栏上方会出现「楼层可见」。

## 面板说明

**工具栏** —— 一行，隐藏数量是主角。

- 左：插件图标 + `楼层可见`（弱文字），点整行展开面板。
- 中：`隐藏 3` 徽标，0 时收起，右侧图标位置不变。
- 右：`定时 2` 徽标表示还有 2 条定时规则待执行。
- 点面板右上角的「收起为状态条」后，工具栏只剩 `3/40 - 隐藏`（隐藏数 / 总数 - 上一条楼层的可见性），
  再点工具栏即可展开，面板里同一个按钮会变成「展开完整工具栏」。

**面板** —— 头部与工具区固定、中间手风琴列表滚动、底部说明固定。

```
楼层可见性   5/10 隐藏 · 2 定时                          [收起] [关闭]
[ 全部 | 用户 | AI ]
[全部可见] [全部隐藏] [清除定时]
最近 [ 2 ] 轮可见                                      [应用]
──────────────────────────────────────────────────────────
⌄  #9  用户  第 9 楼的内容                               (开)
⌄  #8  AI    第 8 楼的内容（已划掉）                     (关)
⌃  #6  AI    第 6 楼的内容    [4 轮后隐藏]               (开)
   在 [4] 轮后 (到点开关) 隐藏                      ✓  ✕
```

- 列表**最新在前**，`#id` 是真实楼层号；点某一层会在它下面展开手风琴面板，再点一次收起，同时只开一个。
- 每行右侧的开关直接控制该层对 AI 的可见性（与酒馆的隐藏状态一致）；隐藏的楼层文字划掉并变灰。
- 展开内容不套卡片：**没有底色、没有描边**，左侧退回 chevron 之后，与楼层号对齐，看起来就是这一行的延续。
- 手风琴里的定时编辑是**一行**：`在 [N] 轮后` + 到点开关（隐藏 / 可见）+ 操作按钮。
- `✓` / `✕` **默认不出现**，只有在轮数或到点开关被改过之后才出现；改回原值又会消失。
- 已有规则的楼层额外显示删除按钮（垃圾桶），随时可以取消规则。
- `Esc` 先收起手风琴，再按一次收起面板；点面板外任意位置也会收起。
- 面板宽度跟随工具栏但上限 520px；手机端铺满视口宽度、开关 40px，编辑行仍保持单行。

## 定时规则怎么算「一轮」

- **一轮 = 一次 AI 回复**（`tavern_events.MESSAGE_RECEIVED`）。
- 规则从**设置那一刻**开始倒数：设「3 轮后隐藏」，接下来 3 次 AI 回复之后才执行。
- 撤回/重新生成也算一轮；`quiet` 静默生成不写进聊天，不算轮。
- 楼层被删除时，对应规则自动失效。
- 规则存在**聊天变量** `tt_message_visibility` 里，跟着聊天走，切换聊天互不影响。

## 已知限制

- 批量操作（全部隐藏 / 可见窗口）不会清掉已设的定时规则；两者冲突时以最后执行的为准。
- 「只让最近 N 轮可见」把第 N 轮之前的楼层（含开场白）一起隐藏；需要开场白时用 `全部可见` 或手动打开该层。
- 定时规则按本地轮次倒数，不跟随酒馆的「回退到某楼层」回溯。
- 筛选只影响列表显示，不影响 `全部可见` / `全部隐藏` / 可见窗口的作用范围（始终是全部楼层）。
- 筛选与「收起为状态条」是个人界面偏好，存在 `localStorage`（`tt-message-visibility:ui`），不随聊天切换。
